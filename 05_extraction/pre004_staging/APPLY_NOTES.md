## 3. Apply order (coordinator)

1. **Preconditions.** R62 is charted, loaded into the v3.0 pilot workbooks and, if wanted, compared with the **v3.0** scripts. After apply, `compare_extraction.py` refuses v3.0 workbooks ("sheet precision_validation lacks columns ['marker_family']"; tested). Confirm that no agent is still reading the live files.
2. **Check:** `bash 05_extraction/pre004_staging/apply_pre004.sh --dry-run`. If a live file changed after staging (for example project_settings stages updated after R62), merge that change into the staged copy, refresh its line in `BASE_SHA256.txt` (`shasum -a 256 <path>` from the repo root), and rerun. `--force` skips the hash stop but is not recommended.
3. **Apply and rebuild:** `bash 05_extraction/pre004_staging/apply_pre004.sh --build`. This copies the files in the fixed order (dictionary/template → manuals → screening incl. calibration plan → synthesis → loader, workbook generator and merge script → protocol EN/CN and execution plan → TeX header → amendments → settings → CHANGELOG → README). It then runs `build_protocol.py` → TeX compile (latex-paper-en `compile.py`, `--outdir build_v3`) → `publish_protocol_pdf.py` → `create_flowchart.py` → `validate_design.py` → `build_workbooks.py --reviewer A --reviewer B` → the three selftests. Without `--build`, it copies only and prints the build commands. The build order matters: `build_protocol.py` removes `pdf_export` from the manifest, so compile and publish must follow before validating.
4. **Verify:** expect validator 27 passed / 0 skipped; extraction workbook 191 fields, 0 undefined, 0 template issues; screening workbook 13 sheets (adds `screen_TI_reviewer_A/B` and `merge_TI`), TI dropdown ADVANCE_TO_ABSTRACT / EXCLUDE_TITLE / AWAITING_CLASSIFICATION with reasons TI01–TI05, FT dropdown includes RETAIN_BACKGROUND and TA dropdown is unchanged; selftests compare 18/18, loader 26/26, merge 49/49 (27 existing + 22 for TI).
